# Private Marks

A small Dalamud plugin for finding the people you manually mark. Hearts, stars,
diamonds and circles are drawn only in your own ImGui overlay. Eight players may
be marked simultaneously; icons can be reused freely.

## Use

1. Run `/pmark`.
2. Click an icon beside a party member, or expand **Nearby / Test Players**.
3. Close the window. The overlay remains visible.

Click an active icon again or the row's **X** to clear it. **Clear All** and
`/pmark clearall` remove both temporary and saved assignments. `/pmark settings`
opens the lightweight settings panel. Search accepts names and world names.

**Background opacity** adjusts the dark backing on world markers and edge
indicators separately from the icon and text. Set it to **0** to remove the
background completely. The setting saves automatically.

**Remember new marks** defaults on. Each marked row also has a **Remember**
checkbox. Changing the default affects future assignments only; changing an icon
preserves that player's persistence preference. Temporary marks clear on territory
change, logout, or plugin unload. Remembered marks restore when the same character
name and home-world ID is loaded again. Renames/world transfers require reassigning.

## Build and install for local development

Requires Windows, .NET 10 SDK, and Dalamud API 15 references. The project uses
the official `Dalamud.NET.Sdk/15.0.0`. Normally XIVLauncher supplies references
under `%APPDATA%\XIVLauncher\addon\Hooks\dev`. If needed, set `DALAMUD_HOME`
to the directory containing `Dalamud.dll` and its accompanying assemblies.

```powershell
dotnet build PrivateMarks/PrivateMarks.csproj -c Release
dotnet run --project PrivateMarks.Tests -c Release
```

Add the absolute path to `PrivateMarks/bin/Release/PrivateMarks.dll` to Dalamud's
development plugin locations in `/xlsettings`, then enable Private Marks through
the development plugin installer. A distributable archive is generated by
DalamudPackager in the Release output. This repository does not install or
publish anything automatically.

## V1 scope and limitations

- Party roster uses supported `IPartyList` enumeration. Full alliance roster
  enumeration is intentionally omitted: current APIs expose address-based
  alliance methods rather than a clean managed collection. Loaded alliance
  players can be selected from Nearby. This is not a full alliance UI.
- World positions come exclusively from loaded `IPlayerCharacter` objects.
  Unloaded players show **Not located** and have no distance or arrow. No roster
  position fallback, extrapolation, hidden identifiers, or retained actor pointers.
- Off-screen arrows use the current supported projection output, including its
  signed direction behind the camera. A degenerate projection is hidden rather
  than assigning an arbitrary direction. No camera memory reads.
- Labels use the first name for compactness; hover/roster identifies the complete
  name and home world. Distance is approximate 3D center-to-center world distance,
  labelled in yalms. Icons, padding and labels follow Dalamud UI scaling.
- Overlay follows fresh positions each frame, without smoothing lag. Death does
  not remove a mark if the actor remains loaded. Loading transitions suppress it.
- Simple label packing and connector lines reduce overlap among eight marks.
  At extremely small resolutions/large UI scales some overlap remains possible.
- These are 2D overlays, not occlusion-aware 3D nameplates: loaded players can be
  indicated through scenery. Game UI hiding and normal Dalamud UI suppression
  are respected. The overlay takes no mouse input.
- There is no network client, marker command, target setter, IPC, game-memory
  write, combat recommendation or action automation in this plugin.
